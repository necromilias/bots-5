## Exact and provider-managed planes remain distinct

The [provider-managed context/Archive v3 contract](PROVIDER_MANAGED_CONTEXT_ARCHIVE_V3.md) is additive. Registered exact adapters retain Phase 6 snapshot 3/context-plan v3 semantics. Normal configured OpenRouter uses provider-managed plan v1 and snapshot 5; explicit developer-test sessions retain their separate non-production accounting boundary. Generic OpenAI-compatible production remains exact/fail-closed. Unknown capability truth does not enable weaker accounting.

Provider-managed selection uses a deterministic local UTF-8/canonical-JSON heuristic, output reserve and configured headroom; the provider owns final admission. It is neither exact prompt-token accounting nor a guaranteed fit. Mandatory material failing local admission is refused before dispatch. Recognized provider context rejection remains a durable error without automatic retry, rebudget or model change. Catalogue/settings/capability provenance and revisions are captured and checked at start. These are accounting-policy/admission differences, not exemptions from unified persistence authority.

0020 adds the separate plan table and receiving-side Archive v3 guards. Downgrade to 0019 refuses retained provider-managed plans, snapshot 5 or v3 import/lineage evidence; an evidence-free downgrade restores the prior guards. Whole-installation backup still captures the internal SQLite database; restore validates the current schema. These extend existing evidence/recovery participation, without changing the public Backup v1 format or reclassifying imported evidence as exact.

## Stream ownership and failure semantics

The final ownership chain is application → router generator → backend generator → provider stream/HTTP body → response/client/transport. Router/backend `aclosing` and the shared HTTP owner make close explicit. Deferred application cleanup first settles the owned pending next-event child, then closes the iterator and preserves genuine child/close failures. It cannot authorize forward database work merely because it owns release. ExecutionManager retains cleanup failures, drains cleanup rather than cancelling it, and application close reports a real drain failure before completing teardown.

Valid stop plus DONE completion does **not** read irrelevant post-DONE tail to clean up. Genuine pre-DONE ReadError/provider failures retain failure classification, partial output, metadata and remote uncertainty. No drain/retry/error swallowing is a replacement for closure. The retained final frozen matrix records zero forgotten cleanup tasks and transport settlement before store release for its tested subjects; retained general resource/restore diagnostics are not converted into a universal clean-shutdown guarantee.
